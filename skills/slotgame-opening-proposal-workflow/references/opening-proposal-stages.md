# Slotgame 開案階段與 Gate

## 階段總表

| 階段 | 主要問題 | 必要產物 | 通過條件 |
|---|---|---|---|
| 0. Context | 現況與來源在哪裡 | 檔案盤點、版本判讀、交付物地圖 | 找到最高版本與可重建來源 |
| 1. Frame | 要做什麼遊戲 | 一句話定位、目標玩家、範圍 | 核心幻想與限制可清楚說明 |
| 2. Core Loop | 玩家每次下注發生什麼 | 主流程、判定順序、停止條件 | 無事件順序歧義 |
| 3. Symbols | 盤面物件如何作用 | Symbol 表、特殊狀態表 | 每個 Symbol 的觸發與例外完整 |
| 4. Main Game | 一般遊戲如何得分 | 狀態機、公式、算分案例 | 案例可由公式重算 |
| 5. Freegame | Feature 如何進入與結束 | 觸發、加局、跨局狀態、結算案例 | Retrigger 與重置範圍明確 |
| 6. Feature Buy | 付費入口有何差異 | 價格、進場、RTP 模型、加局規則 | 與自然 FG 差異逐項列出 |
| 7. Math | 如何形成可驗證數學模型 | 數學交接、模擬版本、測試案例 | 公式可回算、目標與實測分開、上限／重抽有終止條件 |
| 8. Theme/UI | 玩家如何看懂機制 | Symbols 題材、UI 狀態、動畫流程 | 畫面事件與後端事件一致 |
| 9. Package | 如何開案與跨部門交接 | DOCX、PPTX、流程圖、Help、交接文件 | 全部產物同步且可重建 |

## 機制規格模板

對每個特殊機制回答：

1. 何時檢查。
2. 需要哪些符號或狀態。
3. 成立時先後發生什麼。
4. 不成立時如何處理。
5. 是否跨 Spin／跨局保留。
6. 與其他功能同時成立時的優先順序。
7. 得分公式與多個來源的合併方式。
8. 玩家畫面如何顯示。
9. 後端需要記錄哪些欄位。
10. 至少一個成立與不成立案例。

## 修訂流程

當任一已鎖定規則變更時：

1. 記錄舊規則、新規則與修改理由。
2. 搜尋名稱、數值、公式與同義句，不只搜尋章節標題。
3. 建立受影響產物清單。
4. 先更新來源文件與生成腳本，再重新生成衍生檔。
5. 重算所有案例與表格。
6. 重新執行結構、視覺與一致性 QA。
7. 若影響機率模型，標記舊模擬失效並要求重跑。

## Math Gate

Math 階段通過前必須確認：

1. Bet、Coin、Credit、賠率與派彩倍數的單位沒有混用。
2. Main Game、自然 Feature、Feature Buy 的 RTP 關係可由公式回算。
3. Hit Rate、Feature Frequency、回本率與倍率分布都有明確分母及觀察邊界。
4. 倍率統計區分顯示到達與實際套用得獎。
5. Max Award、截斷或重抽規則有最大嘗試次數與終止行為。
6. 重抽、保證得獎或其他條件化機制已納入最終 RTP 與分布。
7. 波動定位通過 Feature RTP 集中度、等待機率與短期報酬檢查。
8. 驗證計畫包含多 Seed、樣本量、95% 信賴區間、逐投注結果與零誤差平衡。
9. 無正式模擬證據的數字仍標為 `待數學驗證`，即使使用者已確認該目標。

## 典型使用者指令的處理

- 「先不用想美術、程式、機率」：只做到玩法與規則鎖定。
- 「鎖起來」：更新決策表及所有已存在的依賴文件。
- 「整理好」：輸出完整規則，不省略公式、例外與重置條件。
- 「照原本格式」：先讀取原檔與版型，再修改內容；不得只模仿文字風格。
- 「執行 1、2，3 不要做」：完成並驗證 1、2，禁止預作 3。
- 「舉一個例子」：使用明確下注值，逐步列出事件、即時得分、狀態變化與總分。
